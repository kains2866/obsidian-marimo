# 测试与验收矩阵

本文全部是计划。既有插件的历史测试通过，不代表 marimo 测试已经通过。每项实测记录必须注明 marimo/Obsidian/Python/Electron 版本、操作步骤、结果、日志与证据路径。

## P0 阻断式可行性检查

| ID | 场景 | 验收要求 |
| --- | --- | --- |
| G01 | 固定 marimo 版本能力 | 保存版本及 edit/pair 帮助；明确哪些文档选项实际不存在 |
| G02 | 本地 edit 嵌入 | Obsidian 内可加载完整编辑器，无 CSP/框架/认证绕过 |
| G03 | HTTP 与 WebSocket 认证 | 无令牌不能获取编辑会话；有效令牌能连接；错误不连接到其他文件 |
| G04 | 编辑、运行、交互 | 文本与代码编辑、响应式更新、滑块和表格均有真实输出 |
| G05 | 保存与关闭 | 修改能落盘，重新打开内容一致；未保存关闭不能静默丢失 |
| G06 | 网页隔离 | 网页无法获得 Node/Obsidian 高权限对象；外链、下载、粘贴行为受控 |
| G07 | 生命周期 | 正常停止及崩溃、取消后没有遗留自有服务器/内核；不杀外部服务 |

G02–G07 任一失败，P1 不进入正式实现。G01 缺少 pair 能力时，P2 保持禁用；不能把 P1 成功当作 P2 成功。

## 功能、故障与竞态

| ID | 场景 | 预期 |
| --- | --- | --- |
| F01 | 无 marimo 首次打开 | 先展示安装目标；只有确认后下载；成功可打开 |
| F02 | 网络中断、证书错误、磁盘满、权限不足 | 分类提示；取消/进度恢复；重试不受旧锁阻塞 |
| F03 | 用户系统 Python/已有虚拟环境 | 不自动修改系统环境；明确实际解释器 |
| F04 | 中文、空格、长文件名 | 无 shell 注入、路径截断或错误文件写入 |
| F05 | 链接逃逸、损坏文件、云端占位文件 | 拒绝危险目标；原文件不修改 |
| F06 | 同文件双标签、不同文件双标签、双窗口 | 前者会话复用，后者状态独立；聚焦正确 |
| F07 | DeferredView、关闭中的 view | 不调用不存在的方法；设置和环境操作不报 TypeError |
| F08 | 确认、探测、安装准备时关闭窗口 | 后续阶段不启动；已取得操作锁必释放 |
| F09 | 端口冲突、启动退出、连接掉线 | 有限重试；不误连陌生服务器 |
| F10 | 运行时删除/切换环境 | 明确拒绝或停止协商；不在活跃 kernel 上卸载依赖 |
| F11 | 源文件外部编辑、改名、移动、删除 | 不覆盖新文件；报告冲突或按设计重连 |
| F12 | 停止、卸载、仓库切换、应用退出 | 保存保护到位，只清理自己拥有的进程与 token |
| F13 | 主题、缩放、IME、快捷键、剪贴板、下载 | 宿主与嵌入页职责明确，无双重快捷键触发 |
| F14 | 大文件、大输出、多标签 | 测量内存和关闭后资源，不以单元测试冒充性能证据 |
| F15 | 同文件切换解释器/双窗口启动 | 独占写者锁不因环境不同而绕过；保存停止旧会话后才能交接 |
| F16 | ready、断连、停止、崩溃及过期的发现记录 | 记录随真实会话变化；停止或死亡不能继续显示可连接 |

## Agent 场景

| ID | 场景 | 预期 |
| --- | --- | --- |
| A01 | Agent 发现两个同名文件 | 使用 vault+realpath+environment+Notebook ID，歧义先确认 |
| A02 | 插件启动和 Agent 自行启动 | owner 正确，插件不能终止 external 服务 |
| A03 | token 错误、过期记录、PID 复用 | 拒绝连接；无认证降级或误杀 |
| A04 | 读变量、改单元格、执行并检查输出 | 分别报告编辑、保存、执行结果，有实际核验 |
| A05 | 用户与 Agent 同时修改 | 冲突可见，不用旧源码覆盖当前编辑 |
| A06 | pair 缺失/协议变化 | 清楚显示不可用，原有编辑和 ipynb 不受影响 |
| A07 | 无工具能力的聊天客户端 | 说明限制，不宣称已经连接执行 |
| A08 | 错误发送到 Agent | 独立显式启用；不默认传输源码、数据、错误信息 |
| A09 | 用户只授权读取或禁止执行 | 不交付完整 pair 凭证；只使用经验证只读工具或静态读取，不能冒充 token 具备细粒度范围 |
| A10 | Agent 编辑引发响应式执行 | 不能把编辑默认为无副作用；执行授权或可靠的禁止自动运行能力必须满足 |

## 既有功能回归

- 标准 ipynb 解析、保存、未知 metadata、attachments、输出及 JSON 草稿保真。
- Properties、Dataview、双链/反链/图谱、标题/块定位和大纲。
- 现有查找、主题、代码背景、撤销、恢复缓存、导出取消与输出安全。
- 环境安装卸载、依赖检测、真实 input/password 输入与运行状态。
- 新增功能关闭时，没有自动安装、端口、后台进程、Agent 连接记录或新文件关联。

## 平台与证据等级

macOS 先做 Obsidian 宿主端到端验证。Windows/Linux 同时做路径、进程树、令牌权限、断连、重试自动化；CI 的 Python/Node 结果不能标记成对应平台 Obsidian GUI 通过。缺少实机证据时列为“未执行”，不能写“全平台完全兼容”。

建议新增 `tests/marimo/*.test.ts`、`tests/marimo/host.integration.mjs` 与明确开关的 `tests/marimo/runtime.integration.mjs`。联网安装集成测试必须使用独立临时仓库，不删除或重装主仓库的环境。
