# 产品与交互设计

## 目标与用户价值

用户在 Obsidian 内打开标准 marimo 文件，编辑、运行及操作交互组件，不必管理终端和 localhost 地址。已有编程 Agent 可以连接同一 Notebook 运行会话，核查变量与输出，再经用户已有工具整理知识库笔记。

成功标准是文件可携带、会话目标明确、关闭可控、执行可核验。界面内嵌并不等于完成 Obsidian 全部原生适配。

## 首版范围

| P1/P2 包含 | 不属于首版 |
| --- | --- |
| 新建 marimo Notebook；显式“用 marimo 打开” | 接管所有 `.py` 或所有 `.md` |
| 官方编辑器的独立工作区标签页 | 重写 marimo 单元格 UI 或响应式执行引擎 |
| 按需安装固定已验证版本、选择本机环境 | 自动升级到 latest、自动修改系统 Python |
| 启动、重试、停止、错误诊断 | 云部署、远程服务器、手机端 Python |
| 官方 pair 能力探测与连接说明 | 自建通用执行 API、重做 AI 聊天客户端 |
| 从本机活动会话中定位正确 Notebook | 默认读取整个知识库、无人授权执行外来代码 |
| marimo 原生 `.py`，另存保持标准格式 | 将现有 ipynb 原地转换或承诺无损互转 |

## 主要流程

### A. 新建与打开

1. 命令面板：“新建 marimo Notebook”；文件夹菜单提供相同入口，默认在选中目录创建不重名的 `.py`。
2. 已有 `.py` 只在显式命令/菜单操作后交给 marimo；识别采用静态内容检查，失败时说明“普通 Python 文件，未作为 marimo Notebook 打开”。不通过 import 来识别。
3. 首次使用展示环境来源、安装位置、需要联网下载的组件，用户点击安装后才开始。安装可取消、可重试；不影响 Notebook 文件。
4. 从下载或外部同步获得的项目，首次执行前确认信任范围。Python 项目配置、导入模块也在信任说明中，不只检查当前 `.py`。
5. 进入 marimo 标签页，顶部插件条显示文件名、环境、服务状态和“连接 Agent”；主体为官方编辑器。

### B. 生命周期与错误

- 状态：未启动、准备环境、启动中、连接中、就绪、连接中断、停止中、已停止、失败。
- “就绪”只说明服务和网页可用；不能代替代码运行成功。执行状态若无法通过受支持接口取得，由官方编辑器展示，插件不猜测。
- 重试只重试失败阶段；权限、网络、版本、解释器、端口和认证失败分别说明。
- 启动失败时保留可复制的脱敏日志；不显示认证令牌。
- 连接断开优先恢复原文件、原服务、原 Notebook ID；目标消失后明确失败，不自动切换其他 Notebook。

### C. 保存与关闭

- 由 marimo 保存文件，Obsidian 不同时打开另一个可写源码编辑器。
- 文件另存、外部修改、移动与重命名需先验证 marimo 固定版本的行为；无法安全维持连接时提示关闭保存后重新打开。
- 多个 Obsidian 标签页打开同一文件，默认引用同一个运行会话；不得无提示创建两套相互覆盖的编辑状态。
- 服务启动后不能把“文件有修改时间”当作“全部编辑已保存”。P0 必须确认官方保存反馈或可靠的离开保护；没有可靠信号时使用明确的保存确认，不伪造已保存状态。
- 关闭最后一个编辑标签页时，先完成保存/离开判断，再停止插件拥有的会话。已授权 Agent 会话仍活动时，提供保留会话或停止并断开的选择；意外断连采用有上限的恢复窗口。
- 插件卸载、仓库切换、应用退出均执行相同清理；不以 view 方法存在为假设遍历 DeferredView。

### D. Agent 入口

“连接 Agent”面板显示当前 Notebook、项目、环境及可用能力；用户可复制适配其客户端的连接说明。连接令牌不作为普通日志或笔记内容展示。官方 pair 连接按实际具备的读取/编辑/执行权限说明，不提供没有底层支持的“只读 pair”开关。

| 路径 | 首版行为 |
| --- | --- |
| Obsidian → Agent → marimo | 使用已有 Obsidian/文件工具定位文件，再读取本机活动会话并使用官方 pair |
| Agent → marimo | 按同一目标直接连接官方会话；不需要焦点停留在 Obsidian |
| marimo 内 AI 面板 | 保留官方功能，凭据由用户配置；实验性 ACP 面板不是首版依赖 |

没有 Obsidian 连接器且没有活动会话时，首版不承诺 Agent 能远程启动 Obsidian 内服务；可提示用户打开文件，或在已有授权下直接使用 marimo CLI。外部自行启动的服务不得被插件接管终止权限。

## 显示、快捷键与可访问性

插件顶部条跟随 Obsidian 主题与 UI 字号；marimo 编辑器优先使用官方主题设置，不跨源注入 CSS。主题、缩放与字体联动须标明支持范围。

编辑器内 Cmd/Ctrl+F、保存、撤销、运行快捷键应由聚焦的 marimo 页面处理；聚焦插件条时由 Obsidian 处理。测试 Tab、Escape、IME、屏幕阅读器标签、复制粘贴与多窗口焦点，不全局截获所有键盘事件。

## 用户可感知的限制

第一版不展示虚假的 Properties、图谱或 Dataview 完整兼容标识。marimo 的 Markdown 格式可另行研究；其 frontmatter 适合原生索引，但与 Python 格式存在官方说明的功能差异。

不暗示“嵌入后更安全”：运行 Notebook 仍以当前用户权限执行 Python。AI 数据是否离开本机取决于用户选择的 Agent/模型服务。
